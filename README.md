# SecAI+ Practice Exam Generator

An adaptive practice-exam generator for CompTIA SecAI+ (CY0-001), hosted on
GitHub Pages. Each exam is **40 questions in 40 minutes**, and the questions a student
misses are weighted to come back.

**Take the exam:** https://unicron47.github.io/secai-plus-practice-exam-generator/

No server, no database, no accounts, no build step: just HTML, CSS and one JS file.

---

## For students

1. Open the site, type your name or student ID, press **Start exam**.
2. One question at a time. **Previous / Next** to move, or click any number in the
   navigator grid to jump straight there.
3. **Flag for review** marks a question; flagged questions appear in a list in the
   sidebar and clicking one jumps to it.
4. Change any answer as many times as you like until you submit or the clock runs out.
5. After the exam, the review screen shows the correct answer and an explanation for
   every question.

Keyboard: <kbd>1</kbd>–<kbd>6</kbd> pick an answer, <kbd>←</kbd>/<kbd>→</kbd> move,
<kbd>F</kbd> flag.

**Your progress lives in your browser, not in the cloud.** Use the same browser on the
same computer each time, or use *Export progress* / *Import progress* to move between
machines. Refreshing or closing the tab mid-exam is safe; the clock keeps running while
the tab is closed.

## How the adaptive weighting works

Every question carries a weight, and exams are drawn by weighted random sampling
without replacement:

```
weight = MISS_WEIGHT[times missed] × STREAK_DECAY ^ (correct answers in a row)
```

Unseen questions weigh 1; a question missed once weighs 8, twice 20, then 35 and 50.
Each correct answer in a row multiplies the weight by 0.4. Up to **60%** of every exam
is reserved for questions the student has missed and not yet answered correctly twice
in a row; the rest keeps new material coming. Tune it in the `CONFIG` object at the top
of [`js/app.js`](js/app.js) and check the effect with `npm run simulate`.

## The question bank

The site reads [`data/questions.json`](data/questions.json), generated by
`tools/build_questions.py` from a master spreadsheet:

| Column | Contents |
|--------|----------|
| A | Question text |
| B | `Multiple Choice` or `Checkbox` |
| C–G | Options 1–5 (option 6 is in column Q) |
| H | Correct answer as option numbers: `3`, or `1,4` for multi-answer |
| J | Exhibit images from the source, one path per line (in `images/`) |
| K | Answer explanation, shown on the review screen |
| L | Text exhibit: a table or command output, shown in a monospace box |
| M–O | Review notes and drafts: **never published** |
| P | Question ID: progress is stored per ID, so rewording a question keeps it |
| Q | Option 6 |

The questions were parsed from an ExamTopics PDF. Where the community's most-voted
answer differed from ExamTopics' suggested answer, the vote was used: on a verified
Network+ bank that choice was right far more often.

### Explanations

`tools/explain/` drafted the explanations with the Claude API. Each question was first
answered **without seeing the key**; the explanation was accepted only when that answer
matched the key with high confidence and passed checks for length (at most 60 words),
naming the correct answer, and not referring to options by letter (students see them
shuffled). Disagreements went to a second model that saw the key, questions with exhibits
were audited blind by a third, and everything else was reviewed by the instructor.

## Running it locally

`fetch()` is blocked on `file://` URLs, so serve the folder:

```bash
npm run serve      # then visit http://localhost:8000
npm install && npm test
```

---

## Known limits

- **Progress is per browser.** `localStorage` is all a GitHub Pages site can use.
  Export/import is the escape hatch.
- **The answer key is in the page**, as it must be for any client-side exam. This is a
  practice tool, not a proctored assessment.
